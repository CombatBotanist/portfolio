# Repository Structure

npm-workspaces monorepo with two packages. The root `package.json` declares the
workspaces and holds the shared build/lint/format tooling; dependencies are
installed once from the root (`npm install`) and hoisted into the root
`node_modules`. Each package keeps its own `package.json` and `tsconfig.json`.

```
portfolio/
├── package.json        root workspace (scripts + shared devDeps)
├── .oxlintrc.json      shared oxlint baseline
├── .oxfmtrc.json       shared oxfmt config
├── website/            @portfolio/website — React SPA (Vite + TanStack Router)
└── cdk/                @portfolio/cdk — AWS CDK infrastructure (TypeScript)
```

## Root scripts

```bash
npm install           # install all workspaces (hoisted)
npm run build         # build website, then cdk (order matters)
npm run build:website # build only the website
npm run build:cdk     # build only the cdk package
npm run lint          # oxlint across the repo
npm run format        # oxfmt across the repo
npm run format:check  # oxfmt --check
npm run test          # run each workspace's test script if present
npm run synth         # build website, then build + cdk synth
```

Build order matters: `cdk`'s `WebsiteStack` deploys `website/dist`, so the
website must build before cdk synth/deploy.

## website/

```
website/
├── src/
│   ├── main.tsx            App entry — mounts RouterProvider on #app
│   ├── router.tsx          createRouter helper + router type registration
│   ├── routeTree.gen.ts    GENERATED by the TanStack Router plugin — do not edit
│   ├── styles.css          Global styles
│   ├── components/         Shared components
│   └── routes/             File-based routes
│       ├── __root.tsx      Root layout (Outlet + devtools)
│       └── index.tsx       "/" route
├── index.html              Vite HTML entry (mounts into #app)
├── vite.config.ts
└── tsconfig.json
```

## cdk/

```
cdk/
├── bin/
│   └── app.ts              CDK app entry — instantiates PipelineStack
├── lib/
│   ├── pipeline.ts         PipelineStack: self-mutating CodePipeline + stages
│   ├── stages/
│   │   └── DeployStage.ts  One deployable stage (hosted zone + cert + website)
│   └── stacks/
│       ├── hostedZone.ts   Imports the existing jguy.net Route 53 zone
│       ├── certificate.ts  ACM cert in us-east-1 for the subdomain
│       └── website.ts      S3 bucket, CloudFront distribution, DNS, deployment
├── cdk.json                app entry = node dist/bin/app.js (compiled)
└── tsconfig.json
```

## Conventions

- Package names are scoped: `@portfolio/website` and `@portfolio/cdk`.
- oxlint/oxfmt config lives at the repo root; each package's `.oxlintrc.json`
  only `extends` the root and adds package-specific plugins/rules.
- CDK stack classes are named `<Thing>Stack` and live one-per-file in
  `lib/stacks/`. Stages live in `lib/stages/`.
- Each stack defines a `*StackProps` interface extending `StackProps`, with
  `readonly` props, and reads shared values (`stage`, `hostedZone`,
  `certificate`, `websiteSubdomain`) through those props rather than
  reconstructing them.
- Cross-stack values are exposed as `public readonly` fields (e.g.
  `CertificateStack.certificate`, `HostedZoneStack.hosteZone`) and passed down
  through stage/stack props.
- The website's `routeTree.gen.ts` is generated — never hand-edit it; add or
  change routes by editing files in `src/routes/`.
